玩家视角

用一个箱子卖东西，五步

这一段可以直接抄进你服的帮助文档。玩家不需要理解档位公式，箱子信息格里能看到自己当前在第几档。

01

拿到出货箱。管理员发放，或者按服务器配方合成。

02

放在田边、棚子里、仓库门口。位置随你。

03

蹲下右键绑定。绑定后这个箱子归你，别人动不了。

04

把作物丢进去。已定价的会被收，没定价的留在箱里。

05

等结算。立刻结算当场到账，定时结算到点一起给，附一张收据。

想先看行情，打 /sellbox prices；想看自己为什么还是 5 万/日，打 /sellbox tiers，它会逐档告诉你差哪一条条件。

指令手册

玩家三条，管理员一整套

主命令 /sellbox，别名 /sb。点标签切换分组。

指令作用权限
/sellbox prices打开今日收购价。按种类排，普通、银星、金星挨在一起，带分页。sellbox.use
/sellbox tiers查看自己的额度档位：当前在第几档、每个条件过没过、下一档差什么。sellbox.use
/sellbox help列出所有子命令。—

玩家其实不需要指令。放箱子、投东西、看界面就够了；tiers 只是给爱研究经济的玩家看的。流水和待补发查询在「管理员」分组。

指令作用权限
/sellbox give <玩家> [数量]直接给玩家出货箱物品。sellbox.admin
/sellbox list <玩家>列出这个玩家名下所有箱子，含世界与坐标。sellbox.admin
/sellbox log <玩家> [页码]查任意玩家的流水。对账、查刷钱、处理纠纷都用这个。sellbox.admin
/sellbox pending [玩家]查待补发队列。不填玩家就是全服。sellbox.admin
/sellbox total <玩家>看累计卖出、今日已用、当前档位、日上限与剩余。sellbox.use
/sellbox total <玩家> 5000000把累计卖出设成 500 万。设的是绝对值，之后继续卖还会往上加。sellbox.admin
/sellbox total <玩家> +500000在当前基础上加 50 万。带 +/- 按增量算，用来补偿或扣罚。sellbox.admin
/sellbox tiers <玩家>逐档打印条件判定明细，含实际值、失败原因、下一档要求。调 PAPI/权限档必备。sellbox.admin
/sellbox top [页数]成交排行，按累计净额排。sellbox.admin
/sellbox reload重载 config、价格表、文案。改完配置打这个，不用重启。sellbox.admin
/sellbox config check打印当前生效的模块开关与关键参数。排查「为什么没结算」从这开始。sellbox.admin

total 改的是「累计卖出净额」，也就是条件档位里的 lifetime。它不动流水日志，只改一个累计值。

指令作用权限
/sellbox setprice <单价>给手里的物品定价。写进 prices.yml，立刻生效。sellbox.admin
/sellbox setprice <单价> <物品id>给指定 id 定价，不用手持。适合批量调某一类作物。sellbox.admin
/sellbox pricing打开定价表。可搜索、可批量、可排序，比手改 yml 快。sellbox.admin
/sellbox prices以玩家视角看今日实价，含季节倍率与销量折价。定完价用它自查。sellbox.use

定价口径只留一个：按「玩家一分钟能产出多少金币」定，别按「这东西看起来值多少」定。

指令作用
/sellbox debug fill <x y z> <id> <数量>往指定坐标的箱子里塞货。测价格、测结算不用真的去种。
/sellbox debug sell <x y z>立刻结算这一个箱子。验证「到点会不会真的给钱」。
/sellbox debug quote <x y z>只算价不结算，打印每件物品的单价与合计。核价用。
/sellbox debug decay <id>查这个物品今天卖了多少、当前折价系数、全服排名。
/sellbox debug seasonfactor <季节> <id>查某个物品在某季节的倍率。确认 0.8 / 1.2 到底命中没命中。
/sellbox debug itemname <id>查这个 id 解析出的显示名。名字显示不对先跑这个。
/sellbox debug place <x y z> [owner]在指定坐标放一个箱子。补回被误删的箱子用。
/sellbox debug bind <x y z> <玩家>强制把箱子绑给某个人，处理「箱子没主人」。
/sellbox debug deposit <玩家> <金额>走经济接口打钱，确认 Vault / XConomy 通路是否正常。
/sellbox debug paypending <玩家>手动把待补发队列结清。
/sellbox debug balance <玩家>查余额与待补发笔数。排查「钱没到账」的第二步。

fill 和 quote 只动箱子/只算价；sell 走真实结算，会写流水、占玩家当日额度。测试请用小号，别拿主号刷。

服主视角

一笔结算，经过七层

知道顺序，调参数时就知道该动哪一层。下面每一层都有独立开关，不用的直接关掉，不会留下 ×1.00 的空行。

基础价 × 销量折价 × 排名折扣 × 季节倍率 × 权限倍率 × 当日卖货折价 → 扣税 → 到手价
01 BASE

基础价

prices.yml 里那一条。这是你唯一需要认真定的数字，后面全是修正。

items: customcrops:onion: 420
02 DECAY

销量折价

同一样东西当天卖得越多，单价越低，到下限为止。折价系数按「本次结算前」的当日销量算，一次结算整批同价；卖完这一批，下一批才按新销量重新折价。count-by 可选全服共享或只按个人算。

decay.count-by: global / player　min-factor: 0.70
03 RANK

排名折扣

全服销量排名靠前的物品再打一层折。默认关闭，想压「只种一种最赚的作物」时再打开。

decay.rank-enabled: false　rank-selection: percent
04 SEASON

季节倍率

对接 RealisticSeasons：当季便宜、反季贵。规则支持通配，一条 customcrops:onion* 同时盖住普通、银星、金星。

当季 ×0.80　反季 ×1.20　无季节 ×1.00
05 MULT

权限倍率

VIP / SVIP 的收购加成。按权限节点匹配，可以叠加，也可以只取最高；op 可以排除在外。

sellbox.multiplier.vip → 1.20　svip → 1.50
06 VOLUME

当日卖货折价

按「本人今天已到账总额」分档，卖得越多单价越低。它跨物品累计，不跨天，也不受别人卖货影响，专门压刷金型农场主。

40万→0.90　80万→0.80　150万→0.70　地板 0.60
07 TAX

税与到手价

乘完所有倍率后扣税，得到真正进钱包的数字。税率 0–100，默认 5%。玩家在箱子信息格里能看到扣了多少。

net = afterMultiplier × (1 − tax%)

第 8 层是「每日额度」，它不在单价里乘，而是在结算时拦总量：今天还能卖多少，由当前档位决定。 下面这个试算器会把七层价格和额度一起算给你看。

全参数试算

一笔卖多少，自己改参数算

这不是只读示例。基础价、销量折价、排名、季节、权限、当日卖货额、税、日上限、产能，全部可以改。 改完立刻看到单价拆解、本单到手、额度能撑多少，以及下一批会掉到什么价。 按单一种物品的一批结算算；箱里混装多种物品时，额度会按槽位逐种消耗，请分开算。

价格计算器 · 所有输入可改

01基础

「结算前已卖」按你服 decay.count-by 口径填：global 填全服，player 填本人。银星、金星是独立物品 id，基础价填对应变种价，不再乘品质倍率。

02倍率

排名和卖货额折价直接填你服实际命中的系数：1.0 = 不打折，0.7 = 七折。季节、权限可先用预设，再改成任意值。

03折价与税

销量折价 = max(下限, 1 − 每件折价率 × 结算前已卖件数)。和插件一样，先算系数，再乘整批；税率 0 = 不扣税。

04额度

日上限填当前档位金额，0 = 不限。今日已入账按税后净额填；单次拦截的口径差异见右侧提示。

v1.7.1 核心

日上限不再只看累计卖出

原来的「累计卖出 30 万 → 每天 20 万」继续可用。现在每个档位可以再挂 PAPI 变量、权限节点， 或者两者混着来。每个档位默认「全部条件满足」，也可以改成「任一满足」。

TYPE 01

累计卖出

税后到账金额的永久累计。适合纯进度解锁，玩家卖得越多，档位越高。

type: lifetime
op: ">="
value: "300000"
TYPE 02

PAPI 变量

等级、在线人数、金币余额、任务进度……只要 PlaceholderAPI 能返回，就能拿来当条件。

type: papi
placeholder: "%player_level%"
op: ">="
value: "60"
TYPE 03

权限节点

给 VIP、赞助档、活动资格单独开额度。配合 negate 还能做「没有某权限才受限」。

type: permission
node: "sellbox.tier.farmer"
negate: false
match: all
默认。一个档位里的条件全部满足才算过。
match: any
任一条件满足就过。适合「等级达到 或 有权限」这种二选一。
selection: best
所有满足的档位里，取日上限最高的。VIP 可以直接跳档。
selection: sequential
按配置顺序逐档解锁，遇到第一个不满足就停，不能跳档。档位金额请从小到大排。
旧写法
min-total: 300000 仍然有效，等价于 lifetime >= 300000，不用重写旧配置。
离线玩家
权限条件一律判不满足，避免离线结算蹭到高额度；PAPI 能解析就解析。
缓存
condition-cache-ms，默认 1000 毫秒。PAPI 变量值变化最多延迟这么久生效；权限每次实时判定。
禁止递归
条件里不能引用 %sellbox_*% 自身变量，插件会直接判失败。
# config.yml · daily-limit 段（金额请按你服经济改）
daily-limit:
  amount: 50000                # 兜底值，0 = 不限
  selection: best              # best / sequential
  condition-cache-ms: 1000
  tiers:
    - name: "新手"
      amount: 50000
    - name: "熟练农户"
      amount: 200000
      conditions:
        - {type: lifetime, op: ">=", value: "300000"}
    - name: "老农"
      amount: 500000
      conditions:
        - {type: lifetime, op: ">=", value: "1500000"}
    - name: "农场主"
      amount: 800000
      match: any
      conditions:
        - {type: papi, placeholder: "%player_level%", op: ">=", value: "60"}
        - {type: permission, node: "sellbox.tier.farmer"}
    - name: "大户"
      amount: 1000000
      conditions:
        - {type: lifetime, op: ">=", value: "4000000"}
    - name: "SVIP"
      amount: 1500000
      conditions:
        - "permission:sellbox.tier.svip"
        - "lifetime>=8000000"

紧凑写法一行一个条件："papi:%player_level%>=60"、 "permission:!sellbox.tier.blocked"。 数字比较用 >= > <= < == !=；文本用 contains / !contains / startsWith / endsWith / matches。 权限节点前加 ! 表示「没有这个权限才满足」。

01

换 jar

用 SellBox-1.7.1.jar 替换旧 jar。只换 jar，不要整目录覆盖配置；首次启动会生成 config.yml、prices.yml、messages_zh_CN.yml 和 sellbox.db。

02

只改 daily-limit

别整目录覆盖。把旧 config 里的 daily-limit 段换成新版，其它价格、衰减、税收、季节参数保持原样。

03

用 tiers 验证

给自己或测试号设置累计金额，打 /sellbox tiers <玩家>，确认每一档的条件判定和预期一致，再开放给玩家。

问答

装之前你大概会问的

我服是 Paper 26.2，能直接用吗？+

能，用 1.7.1，服务端必须 Java 25 启动。26.2 的 BookMeta.pages(List) 返回类型变了，1.7.0 开收据书会 NoSuchMethodError；1.7.1 改用 addPages(Component...)，已在 26.2 build 127 启动并生成两页收据验证。插件仍是 Java 21 字节码，Java 25 可加载。

旧的四档配置要重写吗？+

不用。min-total 继续有效，等价于 lifetime >= 数值。只想用原来的累计解锁，就在 daily-limit 里加一行 selection: best 即可。

PAPI 条件写了，但永远不通过？+

先在控制台打 /papi parse me %你的变量%。返回原样说明变量没注册或扩展没装；返回非数字（比如 Lv.60）时，用 >= 这类数字运算符会判失败，改用 contains 或换一个纯数字变量。

为什么离线玩家的权限档不生效？+

有意为之。离线时无法可靠判断权限，如果放行，离线结算会蹭到高额度。权限条件对离线玩家一律判不满足；累计卖出和能解析的 PAPI 条件不受影响。

best 和 sequential 到底怎么选？+

有 VIP/赞助档、允许直接跳档：用 best。纯农业进度、必须一档一档解锁：用 sequential。后者要求档位金额从小到大排。

改完配置多久生效？+

/sellbox reload 后立刻重算档位。玩家侧的 PAPI 变量值有 condition-cache-ms 缓存，默认 1 秒，最多延迟这么久；权限每次实时判定。

会跟我现有的经济插件打架吗？+

不会。发钱只调 Vault 的 deposit 或 XConomy 的接口，不接管货币、不改余额。哪天换经济插件，这边不用动。

能和商店插件一起用吗？+

能，但建议只让它负责卖。商店管买，种子、肥料、设备那些；出货箱管卖，作物回收。两边都做买卖，价格会互相打脸。

它能干什么，不能干什么
